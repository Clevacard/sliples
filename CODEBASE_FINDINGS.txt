2.2 Custom Step Execution
──────────────────────────
📁 File: /Users/ptrk/Agantis/sliples/backend/app/services/test_executor.py
Lines: 620-730

Process:
  1. Pattern match extracts captured groups as parameters
  2. Parameters passed as dict to custom code execution
  3. Code wrapped in isolated async function:
     ```python
     async def __custom_step__(page, __params__):
         {param_assignments}
         {user_code}
     ```
  4. Code executed via Python exec() with controlled namespace
  5. Only 'page' and '__params__' available to user code

Example:
  Pattern: r'I fill "([^"]*)" with "([^"]*)"'
  Step: 'I fill "username" with "john@example.com"'
  Captured params: {"field": "username", "value": "john@example.com"}
  Code can use: field, value variables

5.3 Custom Step End-to-End Flow
────────────────────────────────

Creation:
  1. User navigates to CustomSteps page
  2. Enters pattern (regex) and Python code
  3. POST /steps with pattern and code
  4. Backend validates pattern is valid regex
  5. Stores in custom_steps table with committed=False

Validation (during scenario parsing):
  1. GET /scenarios or POST /parser/validate
  2. Custom steps loaded for project
  3. Custom patterns checked FIRST (line 173, parser.py)
  4. First matching pattern wins
  5. Returns validation result including custom_step_id

Execution (during test run):
  1. Celery task loads test run
  2. Loads all custom steps from DB (line 155, tasks.py):
     custom_steps[pattern] = code
  3. Executor receives custom_steps dict
  4. For each step:
     a. Match pattern against step text
     b. Extract captured groups as parameters
     c. Build isolated async function with params
     d. Execute via exec() (line 723, test_executor.py)
     e. Capture screenshot/error on failure

  2. Match groups extracted: match.groups()

The environment.variables field is:
  ✓ Stored in PostgreSQL as JSON
  ✓ Exposed in API (GET/POST/PUT endpoints)
  ✓ Managed in frontend (form, editor, display)
  ✓ Loaded in Celery task (line 120, tasks.py)

BUT it is:
  ✗ NOT passed to test executor
  ✗ NOT available to custom steps
  ✗ NOT available to builtin steps
